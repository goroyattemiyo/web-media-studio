## Playback behavior

### Local / YouTube arbitration

Navigation between WMS cards must not pause playback by itself.

Actual playback claims the active source:

- Local actual play -> claims Local and pauses YouTube
- YouTube actual play -> claims YouTube and pauses Local
- `setActivePlaybackTool()` intentionally does nothing and remains only for ToolDeck compatibility

This fixed the earlier problem where merely opening another WMS tab stopped the active source.

### Floating Mini Player

Available away from the full Player:

- source/title
- play/pause
- Local previous/next
- Queue
- Playlist

Important limitation:

- browser/OS background rules still apply
- embedded YouTube screen-off playback on tested Android is unsupported
- do not claim WMS can bypass browser/OS YouTube background suspension

### Implemented search providers

#### YouTube

- official YouTube Data API search
- result -> official WMS YouTube IFrame playback
- result -> Play Next
- result -> authorized Colab Download path

#### Vimeo

- optional provider via `VIMEO_ACCESS_TOKEN`
- result -> official Vimeo embed inside WMS
- result -> provider-neutral Play Queue
- result -> authorized Colab handoff

#### Google Web

- provider slot reserved
- intentionally disabled
- do not fake a public Google Video Search API
- current Google Web Search Service path requires partner/client configuration and video-result validation before enablement

### Search credentials

Search credentials are optional for Cloud Run deployment.

Expected environment variables:

- `YOUTUBE_DATA_API_KEY`
- `VIMEO_ACCESS_TOKEN`

If absent, the worker must still deploy and `/video/providers` must report those providers unavailable instead of breaking the worker.

Last confirmed project state before this handoff: provider credentials had not yet been configured for production search. Verify current provider status before claiming live search PASS.

## Colab Companion v2 — design decision

The user noticed that `irodori-tts-studio` already used the same basic pattern:

Colab -> Gradio `--share` -> `gradio.live` UI

WMS therefore adopts the IrodoriTTS precedent instead of inventing a new runtime model.

Design docs merged in PR #69:

- `docs/COLAB_GRADIO_COMPANION_V2_DESIGN_2026-09-10.md`
- `docs/COLAB_GRADIO_COMPANION_V2_PHASE_PLAN_2026-09-10.md`
- `docs/COLAB_GRADIO_COMPANION_V2_IRODORI_REFERENCE_2026-09-10.md`

Core decisions:

- preserve existing one-cell Localizer fallback
- use separate Gradio app + thin Colab launcher notebook, like IrodoriTTS
- Gradio share URL is temporary/session-scoped
- WMS must not pretend Companion is always online
- no Colab keep-alive/session bypass
- first URL handoff uses query parameters
- `postMessage` is optional later for live no-reload handoff
- iframe is preferred only if real-device Gate 0 proves it
- if iframe fails, use the exact same prepared Gradio URL in a separate tab
- rights confirmation remains explicit per media job
